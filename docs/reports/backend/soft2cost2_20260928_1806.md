# 사용자 정의 인증 — soft2cost2 적용판

> 원본: https://wwwaloha.oopy.io/174e397e-5311-806d-b8c8-d87e02520d69 (사용자 정의 인증, Spring Security 6)
> 대상: `rwkang321/soft2cost2` (커밋 `ff1aba1`) — Spring Boot 4.0.8 / Spring Security / Oracle / MyBatis / Redis / Nexacro
> 목차 순서와 제목은 원본 사이트와 똑같이 두었습니다. 각 절의 **[원본]**은 사이트 내용을, **[soft2cost2]**는 현재 프로젝트에 이미 들어가 있는 방식을 뜻합니다.
> 이 문서는 분석 문서입니다. 소스 수정은 없습니다.

📕 [Spring Security 6] → soft2cost2는 Spring Boot 4.0.8에 포함된 Spring Security 7 계열을 사용합니다.

#### 이전 페이지

[사용자 정의 인증]

> 💡 **[원본]** 이전 페이지(폼 로그인, `UserDetailsService`를 Bean 메소드로 정의하는 방식)에 이어서 진행합니다.

#### 원본 구성 요소와 soft2cost2 구성 요소 대응표

| 원본 사이트 | soft2cost2 | 비고 |
|---|---|---|
| `Users` (사용자 정보) | `auth/model/UserAccount` (record) | `S2C_USER` 테이블 한 행 |
| `UserAuth` (권한 목록) | `List<String> roleCodes` + `List<MenuPermission>` | 역할 코드와, 로그인할 때 계산이 끝난 메뉴 권한 |
| `CustomUser implements UserDetails` | `auth/model/AuthSessionContext` (record) | `UserDetails`를 구현하지 않습니다. Redis에 저장되고 인증 주체(Principal)로 사용됩니다. |

| `UserMapper.java` / `UserMapper.xml` | `auth/mapper/AuthMapper.java` / `mapper/auth/AuthMapper.xml` | Oracle SQL |
| `http.userDetailsService(...)` | `http.addFilterBefore(redisTokenFilter, ...)` | 인증 주체를 토큰 필터가 만듭니다. |
| `@AuthenticationPrincipal CustomUser` | `@AuthenticationPrincipal AuthSessionContext` | 사용자 정보를 가져오는 방법 |

#### application.properties → soft2cost2: `application.yaml` + `application-dev.yaml`

```yaml
server:
  port: ${SOFT2COST2_API_PORT:8081}

spring:
  datasource:
    url: ${SOFT2COST_DB_URL}
    username: ${SOFT2COST_DB_USERNAME}
    password: ${SOFT2COST_DB_PASSWORD}
    driver-class-name: oracle.jdbc.OracleDriver
  data:
    redis:
      host: ${SOFT2COST_REDIS_HOST:localhost}
      port: ${SOFT2COST_REDIS_PORT:6379}
      password: ${SOFT2COST_REDIS_PASSWORD}

# Mybatis 설정
mybatis:
  mapper-locations: classpath:mapper/**/*.xml
  configuration:
    map-underscore-to-camel-case: true

soft2cost2:
  cors:
    allowed-origins:
      - ${SOFT2COST2_NEXACRO_ORIGIN:http://localhost:9091}
  auth:
    session-ttl-hours: ${SOFT2COST2_SESSION_TTL_HOURS:8}      # Redis 세션 유지 시간
    login:
      failure-threshold: ${SOFT2COST2_LOGIN_FAILURE_THRESHOLD:5}  # 연속 실패 시 잠금 횟수
```

#### Users.java → soft2cost2: `auth/model/UserAccount.java`

> ✅ `S2C_USER` 테이블 구조에 맞춘 record 입니다. 원본의 `@Data` 클래스 대신 불변 record를 사용합니다. 원본에 없던 잠금·비밀번호 변경 관련 항목이 추가되어 있습니다.

```java
public record UserAccount(

        Long userId,
        String loginId,
        String userName,

        Long companyId,
        Long siteId,
        Long deptId,

        String passwordHash,

        String authType,              // LOCAL 만 비밀번호 로그인 허용

        String userStatus,            // ACTIVE / LOCKED ...

        Integer failedLoginCount,

        LocalDateTime lockedUntil,

        LocalDateTime passwordChangedAt,
        String mustChangePasswordYn,  // 'Y' 이면 초기 비밀번호 변경 필요

        String useYn

}
```

#### UserAuth.java → soft2cost2: `roleCodes` + `MenuPermission.java`

> ✅ 원본은 `user_auth` 테이블의 `auth` 값(예: `ROLE_USER`)을 `UserAuth` 객체 목록으로 매핑합니다.
> ✅ soft2cost2는 별도 권한 클래스를 두지 않습니다. `S2C_USER_ROLE` + `S2C_ROLE`에서 역할 코드(`ROLE_CODE`, 예: `SYSTEM_ADMIN`)만 `List<String>`으로 읽고, 메뉴 권한은 로그인할 때 계산해서 `MenuPermission` 목록으로 만듭니다.
> ⚠ DB의 역할 코드에는 `ROLE_` 접두어가 없습니다. 접두어는 `RedisTokenFilter`가 붙입니다 (`SYSTEM_ADMIN` → `ROLE_SYSTEM_ADMIN`).

```java
public record MenuPermission(

        Long menuId,
        Long parentMenuId,

        String menuCode,
        String menuName,

        Integer menuLevel,
        String menuType,

        String screenId,
        String formPath,
        String iconName,
        // ... (sortOrder, authLevel, canExcel, canApprove, canClose, canCostView, dataScope)
) {
}
```

#### CustomUser.java → soft2cost2: `auth/model/AuthSessionContext.java`

> ✅ **[원본]** DB에서 조회한 `Users`, `UserAuth`를 Spring Security의 사용자 정보 인터페이스인 `UserDetails`로 감싸 사용자 정의 인증 객체(`CustomUser`)로 만듭니다.
> ✅ **[soft2cost2]** `UserDetails`를 구현하지 않습니다. 로그인할 때 확보한 사용자 정보, 소속(회사·사업장·부서), 역할 코드, 계산이 끝난 메뉴 권한, 발급·만료 시각을 **하나의 record**로 묶어 Redis에 JSON으로 저장합니다. 이후 요청에서는 이 객체가 그대로 인증 주체(Principal)가 됩니다.

```java
public record AuthSessionContext(

        Long userId,
        String loginId,
        String userName,

        Long companyId,
        Long siteId,
        Long deptId,

        List<String> roleCodes,

        List<MenuPermission> menus,

        boolean passwordChangeRequired,

        Instant issuedAt,
        Instant expiresAt

) {
    public AuthSessionContext {
        roleCodes = List.copyOf(roleCodes);
        menus = List.copyOf(menus);
    }
}
```

원본 `CustomUser`의 각 메소드가 soft2cost2에서 어디에 해당하는지:

| 원본 `CustomUser` 메소드 | soft2cost2 위치 |
|---|---|
| `getAuthorities()` | `RedisTokenFilter` — `roleCodes`에 `ROLE_`을 붙여 `SimpleGrantedAuthority`로 변환 |
| `getPassword()` | 없음 — 비밀번호 비교는 `AuthService.login()`이 `PasswordEncoder.matches()`로 직접 수행 |
| `getUsername()` | `AuthSessionContext.loginId()` |
| `isAccountNonLocked()` | `AuthService.login()` — `userStatus = LOCKED` 및 `lockedUntil` 검사 |
| `isEnabled()` | `AuthService.login()` — `useYn = 'Y'`, `userStatus = ACTIVE`, `authType = LOCAL` 검사 |
| `isCredentialsNonExpired()` | `passwordChangeRequired` — `true`이면 `RedisTokenFilter`가 비밀번호 변경·로그아웃 외 모든 요청을 403(E305)으로 차단 |
| `isAccountNonExpired()` | `AuthSessionContext.expiresAt()` — 세션 만료 시각 (계정 만료가 아니라 세션 만료) |

## 서비스

- UserDetailServiceImpl.java → `AuthService.java` (로그인) + `RedisAuthSessionService.java` (세션 저장·조회)

#### UserDetailServiceImpl.java → soft2cost2: `auth/service/AuthService.java`

> ✅ **[원본]** `UserDetailsService` 인터페이스의 `loadUserByUsername()`을 구현하면, Spring Security가 폼 로그인 때 이 메소드를 자동으로 호출하고 비밀번호 비교도 대신 해 줍니다.
> ✅ **[soft2cost2]** `UserDetailsService`를 구현하지 않습니다. `AuthController`가 `AuthService.login()`을 직접 호출하고, 이 메소드가 **사용자 조회 → 비밀번호 비교 → 잠금 처리 → 역할·메뉴 권한 계산 → Redis 세션 발급 → 토큰 응답**까지 모두 처리합니다.

```java
@Service
public class AuthService {

    // ... (필드와 생성자 생략: AuthMapper, PermissionService, RedisAuthSessionService,
    //      PasswordEncoder, LoginAttemptService, ApplicationEventPublisher)

    // login 자체에는 @Transactional 을 붙이지 않는다.
    public LoginResponse login(LoginRequest request) {

        String loginId = request.loginId().trim().toUpperCase(Locale.ROOT);
        loginAttemptService.unlockExpired(loginId);

        // 👩‍💼 사용자 정보 조회 (원본: userMapper.select(username))
        UserAccount user = authMapper.selectUserByLoginId(loginId);

        // 사용자가 존재하지 않더라도 dummy BCrypt hash와 비교한다.
        // (존재하지 않는 아이디만 빨리 실패해서 계정 존재 여부가 드러나는 것을 막는다)
        String passwordHash = user == null || user.passwordHash() == null ? dummyPasswordHash : user.passwordHash();
        boolean passwordMatches = passwordEncoder.matches(request.password(), passwordHash);

        // 원본: if (user == null) throw new UsernameNotFoundException(...)
        if (user == null || !"Y".equals(user.useYn()) || !"LOCAL".equals(user.authType())) {
            throw loginFailed();   // E301, 401
        }

        if (!passwordMatches) {
            if ("ACTIVE".equals(user.userStatus())) {
                loginAttemptService.recordFailure(user.userId(), lockThreshold, lockMinutes);
            }
            throw loginFailed();
        }

        if ("LOCKED".equals(user.userStatus()) && user.lockedUntil() != null && LocalDateTime.now().isBefore(user.lockedUntil())) {
            throw new ApiException("E306", HttpStatus.UNAUTHORIZED, "계정이 일시 잠겼습니다!!!");
        }

        if (!"ACTIVE".equals(user.userStatus())) {
            throw loginFailed();
        }

        // 🔐 권한 조회 (원본: Users.authList)
        List<String> roleCodes = authMapper.selectRoleCodes(user.userId());
        List<MenuPermission> permissions = permissionService.calculate(
                authMapper.selectAllMenus(),
                authMapper.selectRoleMenuAuth(user.userId()),
                authMapper.selectUserMenuAuth(user.userId())
        );

        loginAttemptService.recordSuccess(user.userId());

        boolean passwordChangeRequired = "Y".equals(user.mustChangePasswordYn());

        // 🔐 AuthSessionContext 생성 (원본: new CustomUser(user))
        AuthSessionContext context = new AuthSessionContext(
                user.userId(), user.loginId(), user.userName(),
                user.companyId(), user.siteId(), user.deptId(),
                roleCodes, permissions, passwordChangeRequired,
                null, null
        );

        // Redis 저장 + accessToken 발급 (원본에는 없는 단계)
        RedisAuthSessionService.IssuedSession issued = redisAuthSessionService.issue(context);

        return new LoginResponse(
                issued.accessToken(), user.userId(), user.loginId(), user.userName(),
                roleCodes, passwordChangeRequired, issued.context().expiresAt()
        );
    }
}
```

#### (원본에 없음) `auth/service/RedisAuthSessionService.java`

> ✅ 원본은 로그인 결과를 서버 HTTP 세션에 저장합니다. soft2cost2는 서버 세션을 쓰지 않고(`STATELESS`) Redis에 저장합니다. Nexacro는 원본 토큰을 보관하고, Redis 키에는 토큰의 SHA-256 해시를 사용합니다.

| 메소드 | 하는 일 |
|---|---|
| `issue(context)` | 32바이트 난수 토큰 생성 → SHA-256 해시 → `soft2cost2:auth:v1:session:{해시}` 키에 JSON 저장 (기본 8시간) → 사용자별 토큰 목록(`soft2cost2:auth:v1:user:{userId}:tokens`)에 등록 |
| `find(accessToken)` | 토큰 해시로 Redis 조회 → JSON을 `AuthSessionContext`로 복원 → `expiresAt`이 지났으면 삭제하고 빈 값 반환 |
| `logout(accessToken)` | 해당 토큰 세션 하나만 삭제 |
| `logoutAll(userId)` | 사용자의 모든 세션 삭제 (비밀번호 변경·권한 변경이 커밋된 뒤 이벤트로 호출) |

> ⚠ 참고: CLAUDE.md 코딩 지침 II-1은 "모든 Service는 먼저 Interface를 만들고 class로 구현"하도록 정하고 있습니다. 하지만 현재 `AuthService`, `RedisAuthSessionService`, `PermissionService`, `LoginAttemptService`는 인터페이스 없이 class로만 되어 있습니다. 반대로 `common/i18n`의 `MessageService` → `MessageServiceImpl`은 지침대로 되어 있습니다.

## Mapper

#### UserMapper.xml → soft2cost2: `src/main/resources/mapper/auth/AuthMapper.xml`

> ✅ 원본은 사용자와 권한을 `LEFT OUTER JOIN` 한 번으로 읽어 `<collection>`으로 묶습니다.
> ✅ soft2cost2는 사용자(`selectUserByLoginId`)와 역할(`selectRoleCodes`)을 **따로** 조회합니다. `resultMap` 없이 `map-underscore-to-camel-case`로 record에 바로 매핑합니다.
> ✅ 원본의 회원 가입(`join`), 회원 수정(`update`), 권한 등록(`insertAuth`)은 인증 Mapper에 없습니다. 관리 기능은 `admin/mapper/UserMapper.xml`, `RoleMapper.xml`에 있습니다.

```xml
<mapper namespace="com.soft2cost2.auth.mapper.AuthMapper">

    <!-- 회원 조회 - loginId -->
    <select id="selectUserByLoginId" resultType="com.soft2cost2.auth.model.UserAccount">
        SELECT
            USER_ID,
            LOGIN_ID,
            USER_NAME,
            COMPANY_ID,
            SITE_ID,
            DEPT_ID,
            PASSWORD_HASH,
            AUTH_TYPE,
            USER_STATUS,
            FAILED_LOGIN_COUNT,
            LOCKED_UNTIL,
            PASSWORD_CHANGED_AT,
            MUST_CHANGE_PASSWORD_YN,
            USE_YN
        FROM S2C_USER
        WHERE UPPER(LOGIN_ID) = UPPER(#{loginId})
    </select>

    <!-- 사용자 역할 (원본: user_auth 조인) -->
    <select id="selectRoleCodes" resultType="string">
        SELECT DISTINCT R.ROLE_CODE
        FROM S2C_USER_ROLE UR JOIN S2C_ROLE R ON R.ROLE_ID = UR.ROLE_ID
        WHERE UR.USER_ID = #{userId}
            AND UR.USE_YN = 'Y'
            AND R.USE_YN = 'Y'
            AND UR.VALID_FROM &lt;= SYSDATE
            AND ( UR.VALID_TO IS NULL OR UR.VALID_TO &gt;= TRUNC(SYSDATE) )
        ORDER BY R.ROLE_CODE
    </select>
```

#### SecurityConfig.java

> ✅ **[원본]** `UserDetailsService` Bean을 메소드로 정의하던 방식에서, `@Service` 클래스(`UserDetailServiceImpl`)를 `http.userDetailsService(...)`로 등록하는 방식으로 바꿉니다.

#### RedisTokenFilter.java (원본에 없음, 원본 `CustomUser.getAuthorities()` 역할 포함)

```java
@Component
public class RedisTokenFilter extends OncePerRequestFilter {

    @Override
    protected boolean shouldNotFilter(HttpServletRequest request) {
        if ("OPTIONS".equalsIgnoreCase(request.getMethod())) { return true; }
        String uri = request.getRequestURI();
        // 아래 URL은 토큰 검사 제외
        return uri.equals("/api/v1/auth/login")
                || uri.startsWith("/swagger-ui/")
                || uri.equals("/swagger-ui.html")
                || uri.startsWith("/v3/api-docs/");
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
            throws ServletException, IOException {

        String accessToken = request.getHeader("X-Auth-Token");

        try {
            Optional<AuthSessionContext> session = redisAuthSessionService.find(accessToken);

            if (session.isPresent()) {
                AuthSessionContext context = session.get();
                if (context.passwordChangeRequired() && !PASSWORD_CHANGE_ALLOWED.contains(request.getRequestURI())) {
                    apiErrorWriter.write(response, HttpStatus.FORBIDDEN.value(), "E305",
                            request.getRequestURI(), "초기 비밀번호 변경이 필요합니다!!!");
                    return;
                }

                // 🔐 권한 정보 (원본: CustomUser.getAuthorities())
                // ⚠ SYSTEM_ADMIN → ROLE_SYSTEM_ADMIN 으로 'ROLE_' 을 여기서 붙인다.
                var authorities = context.roleCodes().stream()
                        .map(role -> new SimpleGrantedAuthority("ROLE_" + role))
                        .toList();

                // 인증 주체(Principal) = AuthSessionContext (원본: CustomUser)
                var authentication = new UsernamePasswordAuthenticationToken(context, null, authorities);
                SecurityContextHolder.getContext().setAuthentication(authentication);
            }

            filterChain.doFilter(request, response);

        } catch (RedisAuthSessionService.SessionStoreException exception) {
            SecurityContextHolder.clearContext();
            apiErrorWriter.write(response, HttpStatus.SERVICE_UNAVAILABLE.value(), "E503",
                    request.getRequestURI(), "인증 세션 저장소를 사용할 수 없습니다!!!");
        }
    }
}
```

#### SecurityConfig.java

> 원본과 달라진 점: `@EnableGlobalMethodSecurity` → `@EnableMethodSecurity`, `antMatchers` → `requestMatchers` (람다 방식), 세션 `STATELESS`, CORS(Nexacro 9091 허용), 401·403 응답 전용 처리기 등록, `BCryptPasswordEncoder` 강도 설정.

```java
@Configuration
@EnableMethodSecurity
public class SecurityConfig {

    // ... (필드와 생성자: 위 "RedisTokenFilter 의존성 주입" 참고)

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(bcryptStrength);
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
                // CSRF 비활성화 (토큰 헤더 방식 REST API)
                .csrf(csrf -> csrf.disable())
                // Nexacro(9091) → API(8081) 교차 출처 허용
                .cors(Customizer.withDefaults())

                // 서버 세션을 만들지 않는다 (원본은 폼 로그인 + 서버 세션)
                .sessionManagement(session -> session
                        .sessionCreationPolicy(SessionCreationPolicy.STATELESS))

                // 401 / 403 응답 처리기
                .exceptionHandling(errors -> errors
                        .authenticationEntryPoint(apiAuthenticationEntryPoint)
                        .accessDeniedHandler(apiAccessDeniedHandler))

                // 인가 설정
                .authorizeHttpRequests(auth -> {
                    auth.dispatcherTypeMatchers(DispatcherType.ERROR).permitAll();
                    auth.requestMatchers("/api/v1/auth/login").permitAll();

                    if (swaggerEnabled) {
                        auth.requestMatchers(
                                "/swagger-ui/**",
                                "/swagger-ui.html",
                                "/v3/api-docs/**").permitAll();
                    }

                    auth.anyRequest().authenticated();
                })

                // ✅ 사용자 정의 인증 설정 (원본: http.userDetailsService(...))
                .addFilterBefore(redisTokenFilter, UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }

    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        // 허용 출처: soft2cost2.cors.allowed-origins[0] (기본 http://localhost:9091)
        // 허용 메소드: GET, POST, PUT, DELETE, OPTIONS
        // 허용 헤더: Content-Type, X-Auth-Token, Cache-Control, Pragma, Expires, If-Modified-Since
        // ...
    }
}
```

> ⚠ 원본의 `.antMatchers("/admin/**").hasRole("ADMIN")` 같은 URL별 역할 규칙은 soft2cost2에 없습니다. soft2cost2는 로그인 외 모든 요청에 인증만 요구하고, 메뉴별 권한은 `common/security/PermissionGuard`(`has`, `require`, `requireFeature`, `requireDataScope`)로 검사하도록 되어 있습니다.

### 사용자 정보 가져오기

#### Principal vs Authentication vs User

> 💡 사용자 정보를 가져오는 주요 인터페이스 및 클래스

다음은 Spring Security의 주요 인터페이스와 클래스의 구조도입니다.

```java
java.security.Principal (Interface)
       ↑
Authentication (Interface)
       ↑
UsernamePasswordAuthenticationToken (구현체)
       ↑
getPrincipal()
↳ org.springframework.security.core.userdetails.User
  (implements UserDetails)
```

`Principal`은 최상위 인터페이스이고, `Authentication`은 이를 확장해 인증 관련 기능을 더 제공합니다. `UsernamePasswordAuthenticationToken`은 `Authentication`의 구현체 중 하나이며, `getPrincipal()`로 인증 주체 객체를 돌려줍니다.

✅ **[원본]** 사용자 정의 인증 방식에서는 `getPrincipal()`이 **CustomUser**를 돌려줍니다.
✅ **[soft2cost2]** `RedisTokenFilter`가 `new UsernamePasswordAuthenticationToken(context, null, authorities)`로 만들었기 때문에, `getPrincipal()`이 **AuthSessionContext**를 돌려줍니다.

```java
java.security.Principal (Interface)
       ↑
Authentication (Interface)
       ↑
UsernamePasswordAuthenticationToken (구현체)   ← RedisTokenFilter 가 생성
       ↑
getPrincipal()
↳ com.soft2cost2.auth.model.AuthSessionContext   (UserDetails 구현 아님, record)
      : userId, loginId, userName, companyId, siteId, deptId,
        roleCodes, menus(List<MenuPermission>), passwordChangeRequired,
        issuedAt, expiresAt
```

✅ **[원본]**

```java
public String home(@AuthenticationPrincipal CustomUser authUser, Model model) throws Exception {
    if( authUser != null ) {
        Users user = authUser.getUser();
        model.addAttribute("user", user);
    }
    return "index";
}
```

✅ **[soft2cost2]** `menu/controller/MenuController.java` — 실제 적용된 코드

```java
@RestController
@RequestMapping("/api/v1/navigation")
public class MenuController {

    // @AuthenticationPrincipal 은 RedisTokenFilter 가 SecurityContext 에 넣은
    // AuthSessionContext 를 파라미터로 전달한다. Oracle 을 다시 조회하지 않는다.
    @GetMapping("/menus")
    public List<MenuPermission> menus(@AuthenticationPrincipal AuthSessionContext session) {
        return List.copyOf(session.menus());
    }
}
```

`auth/controller/AuthController.java`의 비밀번호 변경도 같은 방식입니다.

```java
@PostMapping("/change-password")
@ResponseStatus(HttpStatus.NO_CONTENT)

        @AuthenticationPrincipal AuthSessionContext session,
        @Valid @RequestBody ChangePasswordRequest request
) {
    authService.changePassword(session, request);
}
```

이제 Redis에 등록된 **AuthSessionContext 객체**에서 **사용자 정보**(아이디, 이름, 소속, 역할, 메뉴 권한)를 DB 조회 없이 바로 가져올 수 있습니다. 원본처럼 `authUser.getUser()`를 한 번 더 거칠 필요가 없습니다.

| **클래스/인터페이스** | **역할** | **주요 메서드** | **soft2cost2 에서의 구현체** |
|---|---|---|---|
| `Principal` | 인증된 사용자의 기본 정보 제공 (표준 자바 인터페이스) | `getName()` | `UsernamePasswordAuthenticationToken` (`getName()`은 `AuthSessionContext.toString()` 값을 돌려주므로 사용하지 않음) |
| `Authentication` | Spring Security 인증 정보 (사용자, 권한, 인증 상태 등 포함) | `getPrincipal()`, `getAuthorities()`, `isAuthenticated()` | `UsernamePasswordAuthenticationToken` — `RedisTokenFilter`가 생성, 권한은 `ROLE_` + 역할 코드 |
| `User` → `AuthSessionContext` | 인증된 사용자의 세부 정보 | `userId()`, `loginId()`, `roleCodes()`, `menus()` 등 | `com.soft2cost2.auth.model.AuthSessionContext` (record, `UserDetails` 구현 아님) |

- `Principal`: 최소한의 사용자 식별 정보를 제공.
- `Authentication`: 인증 및 권한 관련 정보를 모두 포함. `PermissionGuard.has(authentication, menuCode, level)`가 이 객체에서 `AuthSessionContext`를 꺼내 메뉴 권한을 검사합니다.
- `AuthSessionContext`: soft2cost2에서 사용자 세부 정보를 제공하는 구체적인 객체. Controller에서는 `@AuthenticationPrincipal AuthSessionContext session`으로 받습니다.
